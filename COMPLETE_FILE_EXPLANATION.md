# COMPLETE PROJECT FILE EXPLANATION - Every Single File

This document provides a detailed explanation of EVERY file in the Zoza Services API project.

---

## ROOT DIRECTORY FILES

### run.py
**Purpose**: Entry point to start the Flask application
**What it does**:
- Imports `create_app` from the app package
- Creates the Flask app instance
- Creates all database tables with `db.create_all()`
- Runs the development server on port 5000 with debug mode enabled

**Why it exists**: Provides the simplest way to start the API with `python run.py`

---

### config.py
**Purpose**: Central configuration settings for the application
**What it does**:
- Defines the `Config` class with Flask settings:
  - `SECRET_KEY`: For session/CSRF security (falls back to 'dev-secret-key-change-in-production')
  - `SQLALCHEMY_DATABASE_URI`: Database connection (default: SQLite `sqlite:///kanban.db`)
  - `JWT_SECRET_KEY`: For signing JWT tokens
  - `JWT_ACCESS_TOKEN_EXPIRES`: Token expiration time (3600 seconds = 1 hour)

**Configuration Pattern**: Uses environment variables with fallback defaults

---

### requirements.txt
**Purpose**: Lists all Python package dependencies
**Contents**:
- Flask==3.0.3 - Web framework
- Flask-SQLAlchemy==3.1.1 - ORM
- Flask-Migrate==4.0.5 - Database migrations
- Flask-JWT-Extended==4.6.0 - JWT authentication
- Flask-CORS==4.0.1 - Cross-origin support
- Flasgger==0.9.7.1 - Swagger API docs
- marshmallow==3.21.1 - Serialization/validation
- python-dotenv==1.0.1 - Environment variables
- Werkzeug==3.0.3 - Password hashing
- flask-login==0.6.3 - Session management

---

### database.py
**Purpose**: Database initialization and configuration
**What it does**:
- Creates the SQLAlchemy database instance (`db = SQLAlchemy()`)
- Provides `generate_api_key()` function for generating secure random API keys using `secrets.token_urlsafe(32)`

**Why it exists**: SQLAlchemy must be initialized once and shared across all models to avoid circular import issues

---

### .env
**Purpose**: Environment variables (sensitive, in .gitignore)
**Contents**: SECRET_KEY, JWT_SECRET_KEY, DATABASE_URL

---

### .gitignore
**Purpose**: Tells Git which files to ignore
**Contents**: .env, __pycache__/, .venv/, instance/, migrations/, *.pyc, .pytest_cache/

---

## MIGRATIONS FOLDER

### migrations/env.py
**Purpose**: Alembic migration environment configuration
**What it does**:
- Configures Alembic (database migration tool) to work with Flask
- Provides `get_engine()` to get database engine from Flask-SQLAlchemy
- Provides `get_engine_url()` to render database URL
- Provides `get_metadata()` to get SQLAlchemy metadata
- Defines `run_migrations_offline()` - runs migrations without DBAPI connection
- Defines `run_migrations_online()` - runs migrations with DB connection

**Why it exists**: Required by Flask-Migrate to manage database schema changes

---

### migrations/script.py.mako
**Purpose**: Template for generating new migration files
**What it does**:
- Template used by Alembic when running `flask db migrate -m "message"`
- Contains placeholders for revision ID, upgrade/downgrade functions

**Why it exists**: Defines the structure of new migration files

---

### migrations/README
**Purpose**: Brief documentation
**Contents**: "Single-database configuration for Flask."

---

### migrations/alembic.ini
**Purpose**: Alembic configuration file
**What it does**:
- Configures logging for alembic, sqlalchemy, flask_migrate
- Sets log levels (WARN for root/sqlalchemy, INFO for alembic/flask_migrate)
- Configures console handler for logging

---

### migrations/versions/ (folder)
**Purpose**: Contains database migration scripts
**Why it exists**: Stores versioned migration files (auto-generated by Flask-Migrate)

## APP PACKAGE

### app/__init__.py
**Purpose**: Flask application factory
**What it does**:
1. Creates Flask app with Config
2. Initializes extensions: db, ma, migrate, JWTManager, CORS, Swagger
3. Registers all blueprints (auth, suppliers, products, branches, inventory, categories, orders)
4. Defines custom error handlers for 400, 404, 405, 401, 500 errors

**Key Features**:
- Swagger UI available at `/apidocs/`
- All error responses follow consistent format

---

### app/extensions.py
**Purpose**: Flask extension initialization
**What it does**:
- Creates `ma = Marshmallow()` instance for serialization
- Creates `migrate = Migrate()` instance for database migrations

**Usage**: Imported in `app/__init__.py` to initialize extensions with the app

---

### app/models.py
**Purpose**: Alternative model definitions (legacy/simplified)
**Contents**: Quick model definitions for User, Branch, Category, Product, Supplier, Stock, Order
**Note**: The actual models are in each module's domain folder

---

### app/schemas.py
**Purpose**: Marshmallow schemas for serialization (alternative)
**Contents**: UserSchema, ProductSchema, CategorySchema, MessageSchema
**Note**: Used for validating input and serializing output

---

### app/api_response.py
**Purpose**: Standardized API response formatting utility
**Methods**:

|--------|--------|-----|
| success() | 200 | Successful operations |
| error() | 400 | Validation errors |
| validation_error() | 400 | Missing fields |

| forbidden() | 403 | Permission denied |

## ARCHITECTURE PATTERN

Each module follows this pattern:

```
Module/
├── domain/     → Database model (SQLAlchemy)
├── routes/     → API endpoints (Blueprint)
├── service/    → Business logic (Service class)
├── repo/       → Database operations (Repository class)
└── schema/     → Serialization (Marshmallow - optional)
```

## DATA FLOW

```
HTTP Request
     ↓
Routes (verify JWT, check permissions)
     ↓
Service (business logic, validation)
     ↓
Repository (database CRUD)
```
